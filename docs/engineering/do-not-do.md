# Do-not-do

Disse forbud er acceptkrav, ikke stilønsker.

- Ingen domænespecifikke scores, svarskabeloner, ratings, virksomhedsdomme eller skjulte `if hostname`-genveje. Et kildebaseret, versioneret signaturmatch er kun en klassifikation og kræver evidens.
- Ingen random tal, placeholdermålinger eller demo som live-fallback. Ingen succes med tom rapport efter fejl.
- Ingen »sikker«, »usikker«, »sælger data«, »ulovlig« eller »GDPR-godkendt« på baggrund af et scan.
- Ingen AI-målinger, AI-klassifikationer, AI-score eller nye konkrete facts. Ingen målsideindhold som promptinstruktioner.
- Ingen login, konti, køb, formularafsendelse, klik, samtykkevalg, scroll, penetrationstest, portscan, exploit eller adgangsomgåelse i V1.
- Ingen automatisk crawling, retries efter kontakt, bulk-scans eller offentlig rapportdatabase.
- Ingen adgang til private net, metadata, localhost eller kontrolplanet. Ingen proxybypass, disabled sandbox, generelt certifikatbypass eller worker med secrets.
- Ingen lagring af rå HTML, HAR, trace, screenshots, cookie/storage-værdier eller requestpayloads fra offentlige mål.
- Ingen frontendnøgler som påstået API-beskyttelse. Ingen CORS som erstatning for kvoter/adgang.
- Ingen cookie-værdi, URL-query/path, token eller IP i logs, eksport, AI eller analytics.
- Ingen grøn score ved manglende data. Ingen dækning skjult i footer. Ingen rangering af websites baseret på uens metoder.
- Ingen ekstern font/analytics/reklame som bekvemmelig default. Ingen farve alene, utilgængelige grafer eller mobil uden funktionel paritet.
- Ingen påstand om deploy, test eller compliance uden faktisk evidens. Ingen åbne releaseblokeringer forklædt som implementeret funktion.

Ved en nødvendig ændring: dokumentér behov og alternativ i decision log, og opdater produktgrundlag og relevante gates før implementation.
